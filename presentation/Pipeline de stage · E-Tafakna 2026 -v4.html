01 · Contexte

Pourquoi ce stage ?

Suivre l’évolution des lois de 14 pays à la main est lent, coûteux et source d’erreurs. L’objectif : automatiser la collecte, structurer le droit et construire les fondations d’une IA fiable.

❝ E-Tafakna construit un AI Legal Operating System pour 14 pays. Une IA juridique qui hallucine une loi est un risque légal grave. Ce stage a posé les fondations documentaires qui évitent ce risque : données structurées, sources officielles, citations vérifiables. ❞Fil rouge : « Le modèle ne doit jamais inventer le droit. »
🔭

Centraliser & veiller

Surveiller automatiquement journaux officiels et décrets (MENA + Europe), sans intervention humaine.

🧩

Rendre l’information intelligente

PDF bruts ou scannés → articles JSON nettoyés, enrichis (résumés, sanctions, obligations).

💬

Alimenter un RAG

Questions en langage naturel → réponses sourcées, à jour, avec articles cités.

class SourceAdapter(Protocol):
    source_id: str   # ex. "fr-legifrance"
    def discover(self) -> list[str]: ...
        # références disponibles

        # nouveau / modifié (SHA-256)
    def fetch(self, ref) -> RawDocument: ...
        # octets bruts + métadonnées
    def extract(self, raw) -> ExtractedText: ...
        # texte article par article

Pydantic v2 Schema

Contrairement aux approches RAG naïves qui découpent des documents en morceaux arbitraires de 500 tokens ("chunking aveugle"), Legal Brain respecte l'unité de droit :

  • Identifiant déterministe unique : ex. fr-legifrance-art-L1234-1
  • Lien hiérarchique : Relié au parent_document_id (Loi n°...), chapitre et section.
  • Drapeaux juridiques booléens : has_obligations, has_penalties, has_deadlines.
  • Traçabilité certifiée : content_hash_sha256 pour garantir l'absence d'altération.

💬 Pipeline RAG : Recherche Hybride & Citations Vérifiables

Comment l'API /chat garantit qu'aucune réponse juridique n'est inventée en liant chaque assertion à son article source.

1. Question & Extraction d'Entités Query Engine
L'utilisateur soumet sa question. Le système génère simultanément le vecteur de requête (dense embedding via Jina AI / BGE-M3) et extrait les mots-clés juridiques pour la recherche lexicale.
2. Recherche Hybride (BM25 + Cosinus) Hybrid Retriever
Exécution en parallèle :
• Recherche vectorielle : Capture la sémantique et les synonymes juridiques.
• Recherche BM25 : Assure le matching exact des termes légaux et numéros d'articles.
Fusion des scores par Reciprocal Rank Fusion (RRF) pour extraire les Top-5 articles.
3. Prompt Augmenté & Garde-Fou Strict Grounding
Le contexte injecté dans le LLM contient uniquement les extraits des articles officiels sélectionnés, avec une consigne stricte : "Tu es un juriste certifié. Si la réponse n'est pas dans les articles fournis, dis que tu ne sais pas. Cite systématiquement l'article_id."
4. Synthèse avec 'cited_article_ids' Output Certifié
Le modèle génère une réponse claire et retourne dans le payload JSON la liste cited_article_ids. L'utilisateur peut cliquer pour inspecter le texte de loi original dans son contexte officiel.

06 · Architecture & stack

🏗️ Séparation des responsabilités

Les octets bruts confidentiels restent dans la zone de calcul ; seul le texte extrait et les vecteurs partent vers l’index de recherche.

🖥️ OVH Compute

Scrapers, OCR Tesseract, déduplication, LLM auto-hébergés (vLLM / Ollama). Les PDF bruts n’en sortent jamais.

🐘 PostgreSQL + MinIO

Système de référence : versions, horodatage, hashes SHA-256, archives brutes S3.

🔍 Azure AI Search

Modèle de lecture dérivé : texte d’articles + vecteurs, recherche hybride avec filtres pays / date / domaine.
